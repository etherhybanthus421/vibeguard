The problem with vibe-coded code

LLMs are great at writing code that compiles. They're terrible at noticing what they silently broke.

01It looks right

Clean formatting, confident names, plausible logic. Your copilot's output has never once asked you to double-check it.

02It's statistically buggy

Empty catch {}, dereferenced nulls, invented env vars — these are the most frequent patterns in AI-generated diffs, because they're the ones the model "smoothes over".

03It ships anyway

A human review reads the diff like a novel. vibeguard reads it like a diff — line by line, every time, in milliseconds, on every commit.

Questions, answered

Is this another LLM doing the review?

No. vibeguard is deterministic, regex-based static analysis. It's fast (milliseconds per file), offline, and free. It also never agrees with you — rules are rules.

Does it upload my code anywhere?

Never. Everything runs locally in your repo (and this page runs entirely in your browser). vibeguard has zero network calls and zero telemetry.

Will it block my legit code?

All rules default to error only when they're near-certain (hardcoded keys, empty catches, null derefs, missing env vars). Everything else is a warning. You can tune or disable any rule in .vibeguard.yaml.

Can I use it in CI?

Yes — vibeguard check --json outputs machine-readable results with stable exit codes (0 clean, 1 blocked, 2 broken). Drop it in any GitHub Action or pipeline.

Is it actually free?

Free, open-source, MIT licensed. No SaaS, no account, no credit card. Star it if it earns it.
